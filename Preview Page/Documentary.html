Architecture Overview

Escape Of Matrix (E.O.M) is a state-of-the-art local-first application designed to gamify every element of your life. By combining modular components with an RPG progression system, you can build positive habits, manage transactions, log workouts, and track progress under one private workspace.

💡 Privacy First Principle
Your data never leaves your device. E.O.M uses a synchronized local storage layer bound to a Zustand state manager. Backup files are exported to your local file system directly.

The core codebase is structured as a single-page React application powered by Vite, with multi-platform wrappers:

  • Vite + React: Handles responsive rendering, dynamic components, and reactive states.
  • Zustand: Directs user state, transaction ledgers, workout logs, habit histories, and AI parameters.
  • Capacitor (iOS & Android): Transpiles and syncs front-end code directly into native mobile builds for iPhone and Android devices.
  • Electron: Provides cross-platform desktop shells for macOS (.dmg) and Windows (.exe).

🔒 Local-First Privacy & Zero-Knowledge Security

A foundational architectural pillar of E.O.M OS is absolute user privacy and sovereignty over personal data. Unlike traditional SaaS platforms that upload your personal life logs to centralized cloud servers, E.O.M operates on a strict Local-First & Zero-Knowledge architecture.

🛡️ Public GitHub Safety Guarantee
No user data ever touches GitHub or public repositories. The GitHub repository contains only the front-end source code, build scripts, and static assets. Your passwords, profile attributes, financial transactions, habit history, and journal reflections remain exclusively stored inside the sandboxed local storage of your physical device.

Password & Profile Recovery

Because E.O.M is 100% decentralized and local-first, there are no remote servers to reset your password. You have full transparency and multiple ways to access your credentials:

  • In-App Recovery: On the Login screen, click "Forgot Password" and type your Username. The app will immediately display your local backup password on screen.
  • DevTools Inspection (Desktop): Press Cmd + Shift + I (Mac) or Ctrl + Shift + I (Windows) in the Electron app ➔ open the Application tab ➔ select Local Storage ➔ inspect os_profile to view your full JSON profile.
  • Offline JSON Backups: Use the Profile Settings panel to export an encrypted .json backup file or configure an automatic daily backup folder.

Quick Start & Setup

Set up the development environment on your local macOS workstation:

Prerequisites

Ensure you have Node.js (v18+) and npm installed. Check by running:

node -v
npm -v

Installation Steps

1. Clone the project and navigate into the workspace directory:

git clone https://github.com/FRX132/E.O.M.git
cd E.O.M

2. Install package dependencies:

npm install

3. Launch Vite development mode:

npm run dev

The application is now hosted locally, usually at http://localhost:5173.

🔄 Multi-Device Synchronization & Update Workflow

When new features or code fixes are deployed, here is how each device platform receives the update while keeping all existing local user data 100% intact:

1. Web & PWA Users (Instant Cloud Push)

Pushing commits to main automatically triggers a Vercel build. Mobile Safari / Chrome PWA users receive the updated bundle automatically on app reload or via the Service Worker cache refresh banner.

2. macOS Desktop (.dmg Distribution)

npm run electron:build

Generates a fresh .dmg in release/Life Planner OS-x.x.x.dmg. Dragging the new app into /Applications overwrites the executable binary but leaves ~/Library/Application Support/eom/ untouched. Your credentials and logs remain perfectly intact.

3. Windows Desktop (.exe Installer)

npm run electron:build:win

Produces an installer package in release/. Running the installer updates the binary while preserving %APPDATA%\eom.

4. iOS Native App (iPhone & iPad via Xcode)

npm run build
npx cap sync ios
npx cap open ios

In Xcode, click Product ➔ Archive or press Cmd + R to deploy to your connected iPhone or push to TestFlight.

5. Android Native App

npm run build
npx cap sync android
npx cap open android

💰 Finance Hub & Performance Memoization

The Finance Hub (Expense Tracker) is built to manage capital entries, monthly recurring subscriptions, budgets, and net worth tallies.

iPhone Input Typing Lag Fix

In webview wrappers (like Capacitor on iOS), re-rendering huge lists on every single keystroke causes CPU spikes, making text input extremely laggy. E.O.M uses a multi-tier optimization strategy to prevent this:

⚡ Performance Implementation Details
  • Local Key-State Bounds: Input values write to local component states (e.g. useState) on keystroke.
  • Deferred Store Sync: Zustand store writes are deferred until onBlur or Enter key presses, keeping inputs lag-free.
  • React.memo Subcomponents: Rows are extracted into <ExpenseRow> and <AssetRow> wrapped in useMemo, eliminating unnecessary calculations.
  • Key-Based Reset Sync: A hash combination (e.g. key={id-name-amount}) is bound to rows, allowing values to sync automatically when changed externally without firing side-effects.

📱 Capacitor & iOS Xcode Guide

Deploying your React code to run native 1:1 on your iPhone or simulated Apple environment:

Step-by-Step Compile Workflow

1. Open your terminal in the workspace directory and build the production bundle:

npm run build

This creates static HTML, JS, and CSS resources inside the dist/ directory.

2. Copy the files into the Xcode native project:

npx cap sync ios

3. Launch Xcode and compile:

npx cap open ios
⚠️ Bundle Sync Required
Always run npm run build && npx cap sync ios after modifying React components to update the native iOS project files.

🛠️ Platform Troubleshooting

Here are some common platform issues when building E.O.M:

Electron API Blocks in Web and iOS

E.O.M contains desktop features like PDF backups that use window.electronAPI. In Web browsers or iOS WebViews, this will throw an undefined error if not properly guarded: 

// Safe API execution pattern
if (window.electronAPI) {
    window.electronAPI.backupData(payload);
} else {
    console.log("Running in non-desktop client: Fallback to local storage export.");
    // Web/Capacitor backup export logic
}
